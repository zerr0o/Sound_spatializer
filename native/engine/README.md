# Sound Spatializer native engine

This directory is an independently buildable C++20 engine. It contains the real-time DSP core, the Windows WASAPI loopback/render backend, the per-user named-pipe protocol, scene persistence, and dependency-free CTest coverage.

```powershell
cmake -S native/engine -B build/engine -G "Visual Studio 17 2022" -A x64 `
  -DCMAKE_TOOLCHAIN_FILE="C:/Program Files/Microsoft Visual Studio/2022/Community/VC/vcpkg/scripts/buildsystems/vcpkg.cmake"
cmake --build build/engine --config Debug
ctest --test-dir build/engine -C Debug --output-on-failure
```

`libmysofa` is mandatory when `SOUND_SPATIALIZER_ENABLE_MYSOFA=ON` (the default); configuration fails if it cannot be found, so a distributable cannot silently lose measured-HRTF support. Only an explicitly configured development build may use `-DSOUND_SPATIALIZER_ENABLE_MYSOFA=OFF`. In that build, personal SOFA imports are rejected. A non-analytic profile ID without a verified SOFA path is also rejected and surfaced in engine status; it never silently selects the deterministic analytic development profile. The analytic profile is intentionally not presented as SADIE, KEMAR, individualized, or perceptually equivalent to a measured HRTF. The current libmysofa path uses libmysofa's spatial lookup plus fractional application of its per-ear delays; it does not claim separate ITD/spectral interpolation or offline spherical preprocessing. Canonical SOFA paths are cached, with at most 16 unique personal HRTFs retained per process so the audio callback never destroys one still in use.

The direct L/R renderer accepts HRIRs up to 4,096 samples (85.3 ms at 48 kHz). Taps 0–511 use the existing SIMD time-domain FIR, so their algorithmic latency remains exactly zero. Taps 512–4,095 use uniform 128-frame partitions and a 256-point overlap-save FFT. Because the first partitioned tap is already delayed by 512 samples, each completed input block is rendered four blocks ahead: the tail adds no delay beyond the delay encoded in the HRIR itself. FFT plans, spectra, input history, dual morph filters and future-output blocks are allocated once in the convolver constructor; `set_filters()` and `process()` allocate nothing. Crossfades render both complete filters and rebuild all not-yet-played tail blocks when a morph is interrupted. The 4,096-sample bound includes a reserved 64-sample libmysofa delay budget; larger datasets are rejected rather than truncated.

Two colourations produced by the rendering method itself are corrected, and both are measured by the test suite rather than assumed. First, provider neutralization: a SOFA file has no absolute level convention and libmysofa normalizes on whichever measurement minimizes azimuth plus elevation, which leaves the shipped SADIE profiles about 10 dB hot and pins the true-peak limiter. The loader power-averages every response, smooths to a third of an octave and designs a 128-tap minimum-phase inverse whose level part is untapered and whose spectral part fades out below 300 Hz and above 15 kHz; because the corrected component is direction-independent, one stereo FIR on the binaural bus is equivalent to correcting all thirty-six paths and it also covers the reflected field. Measured on SADIE D2, a correlated signal through the default pair drops from +15.6 dB to +5.5 dB, and the shipped sets prove to be already diffuse-field equalized so their correction is a nearly flat attenuation. Second, phantom-centre compensation: both emitters of a pair reach both ears, so correlated content combs by 7 to 11 dB at a frequency that follows the emitter angle. The preparation worker folds a correction into the bank itself — `H'left = [C*(Hleft+Hright) + (Hleft-Hright)]/2` and its mirror — so the convolver, its morphing and the sparse window slots are untouched; `C` is designed from the interference factor rather than from the response magnitude, so pinna notches survive. Residual ripple is under 3 dB, hard-panned content shifts by at most 4.9 dB, and the correction is switchable through `hrtf.phantomCentreCompensation`. The design is cached per pair and redesigned only when an emitter moves more than about two degrees.

For hardware operation, `captureProvider: "native-driver"` discovers the Sound Spatializer render endpoint automatically from its stable property keys and contract version; no display-name matching is used. `captureProvider: "external-render"` instead requires both an explicit active render endpoint ID in `captureEndpointId` and an explicit, distinct physical `outputDeviceId`. An external source carrying the Sound Spatializer marker is rejected, as are source/output IDs that differ only by case. The `set-audio-route` command changes all three values atomically: a failed restart restores the previous scene and running route. `--virtual-endpoint` and `SOUND_SPATIALIZER_VIRTUAL_ENDPOINT_ID` remain native-provider test overrides only; they are not persisted or treated as external-provider configuration. The engine relies on Windows device policy for third-party driver trust and does not claim to authenticate an endpoint from its display name. `--mock-audio` keeps the same engine and IPC path while replacing hardware I/O for local development.

For endpoints whose shared-mode mix already is stereo IEEE-float 48 kHz, both shared streams query `IAudioClient3::GetSharedModeEnginePeriod`; low-latency capture requests the minimum valid fundamental multiple and compatibility mode requests the first valid multiple at or above 256 frames. The loopback client attempts `InitializeSharedAudioStream`, but Microsoft's [IAudioClient3 contract](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient3-initializesharedaudiostream) only documents `EVENTCALLBACK` among its supported stream flags while [loopback recording](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording) documents `IAudioClient::Initialize`. A stack that rejects custom-period flags or an endpoint with another uncompressed shared mix format is therefore reactivated and opened through `IAudioClient::Initialize`; the latter path explicitly requests stereo float32/48 kHz with `AUTOCONVERTPCM` and `SRC_DEFAULT_QUALITY`. Exclusive Pro rendering never uses automatic conversion: it probes stereo 48 kHz float32 first, then signed PCM32, trying correct `WAVEFORMATEXTENSIBLE` descriptions before the legacy stereo forms recommended for older two-channel drivers. DSP remains float32; PCM32 endpoints receive a saturating, non-finite-safe conversion in a preallocated final-render scratch buffer. `renderSampleFormat` reports `float32`, `pcm-s32`, or `unknown`. Endpoint invalidation and service-stop errors are never hidden by these fallbacks. Diagnostics publish the resulting current period, or the buffer size when the legacy stack cannot report it.

The event loop services the physical renderer before capture on render wakes. In shared mode it may also use current padding after a capture-only wake; in event-driven exclusive mode it consumes exactly one complete endpoint buffer only after the render event, as required by WASAPI, and primes the first buffer before `Start`. Loopback work is bounded to four packets and at most one complete capture buffer per wake, so a continuously queued capture endpoint cannot make the render deadline unbounded. Device invalidation and Windows Audio service failures stop both streams, are exposed through an allocation-free atomic code, and trigger WASAPI client recreation with a 250 ms–2 s bounded backoff after the MMCSS section is torn down. This path still requires physical low-period, fallback, backlog and hotplug qualification.

`SoundSpatializer.Engine.exe --autostart` uses the Windows GUI subsystem and creates no console window. A `Local` mutex keyed by SID and session enforces one engine instance; a second launch exits successfully. Control/status uses `\\.\pipe\SoundSpatializer.Engine.v1.<SID>.<SessionId>` and head pose uses the independent inbound-only `\\.\pipe\SoundSpatializer.Pose.v1.<SID>.<SessionId>`. Both are protected by a SID-only ACL, remote-client rejection and `FILE_FLAG_FIRST_PIPE_INSTANCE`; a monotonic gate shared with the legacy pose framing prevents cross-pipe reordering.

The audio callback performs no logging, file/network I/O, waits, mutex acquisition, or dynamic allocation. Scene changes are transferred through a fixed SPSC command queue and at most one is applied per callback; its index atomics are compile-time required to be lock-free. On x64, the WASAPI/MMCSS worker enables FTZ and DAZ for its processing lifetime and restores the previous MXCSR on teardown, preventing denormal tails from creating CPU spikes. HRTF objects are retained until audio shutdown so a real-time callback never owns or destroys them. A dedicated latest-wins preparation worker is the sole production caller of `IHrtfDatabase::query`: the callback publishes pose/scene requests through an atomic mailbox and consumes immutable preallocated result slots through bounded SPSC index queues. Direct filter-bank construction and the 32-point room projection therefore never run on the MMCSS callback. A scene/profile transition keeps its 4,800-frame horizon when a newer pose arrives; the replacement target uses the remaining scene-transition frames rather than restarting an abrupt 64-frame pose morph.

The rectangular-room implementation is an auralization scaffold: order-2 image sources preserve three-band absorption/diffusion, feed an order-3 ACN/SN3D field, and a separately switchable 16-line three-band FDN supplies the diffuse tail. Every order-3 channel and the rotated first-order FDN field reach the headphones through 16×2 time-domain FIRs projected from a fixed, symmetric 32-point HRTF quadrature. The decoder preserves HRIR spectrum and ITD, is fully preallocated, and morphs filter changes. To keep that 32-path reflected-field matrix bounded, it projects the first 512 taps of longer HRIRs; only the two direct loudspeakers use the complete partitioned tail. Its 32 bounded HRTF lookups and FIR projection run on the latest-wins preparation worker; the callback only applies the ready fixed-size matrix. The worst-case 16×2×512-tap convolution still requires qualification on reference hardware before room mode can be called professional. The model is not a certified prediction of a real room and does not model diffraction or low-frequency modes.

The input warning `potentiallyBinaural` is a conservative, hysteretic ITD-correlation heuristic. It never changes routing or bypass state and can produce false positives or negatives; it exists only to warn the user that spatializing an already-binaural programme may be undesirable.
